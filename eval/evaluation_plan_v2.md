## 1. Benchmarks, scope and data roles

- **Primary Tier 2 benchmark: v2.0** (Team B's specs after native review, frozen as `FROZEN_v2.0.json`), generated by
  `tier2.generate_tier2_v2` as **one package over all final specs** and run through all four configurations (C/D x gate off/lexicon):
  new inference for every conversation. Reusing the v1.0 runs for the 62 unchanged pairs was rejected for the primary result: it would
  mix two conversation generations (banks, seeds, distractor sampling) in one metric for a saving of 62 conversations.
- **Bridge table (no inference):** the v1.0 runs relabelled with the v2 labels on the 62 unchanged retained pairs
  (`tier2.build_label_dir`; `t2s_t1_0191` and German excluded), reported separately as "v1.0 conversations, v2 labels".
- **Mirror:** no v2 mirror arm. v1.1m stays a v1 diagnostic only.
- **Splits (Team B):** dev 96 (all 63 retained pairs + 33 new), test 30 (new only). **Exposure, disclosed with every test result:** the
  test sentences and labels were given to an LLM verifier by Team B and sit in the delivery folder; Team A saw per-stratum test counts
  (language x class x relation) in the delivery audit, but no test sentence or per-pair label; Member 3 states the lexicon was written
  without reading specs or labels; no system component (judge prompt or model, QA model, lexicon, tau) is changed after the delivery.
  Rule: test remains the held-out set; scoring tools refuse it before the freeze (`score_v2 --split`); every lexicon or judge diagnostic is
  run on dev only (`judge_readiness check` reads dev only). If Team B replaces the test set with newly authored items before the freeze,
  the new set is the held-out set and the exposed one moves to dev.
- **Scored classes:** kinship, honorific_register, name_variant, and contextual_qualifier (Team B's new class; gold-different only, so
  FCR only). Overall = all four; sensitivity: the three v1 classes only.
- **Scope rule (settled):** a language is named in a result iff its items are native-reviewed and frozen, ran through every configuration of
  the result, and, for Config C, the judge passed a frozen validation in that language (§6). Per relation n >= 20 for a confirmatory
  claim, otherwise "indicative". With the delivered counts Marathi (11 different / 12 same) and Gujarati (11 / 11) can only ever be
  indicative; Hindi (46 / 35) can be confirmatory on the full set, never on test alone (all test cells n < 20).
- **Exclusions (listed, decided before scoring):** pairs Team B's review marks ambiguous or invalid; specs that fail generator validation
  and are not corrected by the freeze; German (out of v2).

## 2. Metrics

- **Merged (primary): final-memory-record level** (same union-find record); **direct pair** secondary, always reported.
- **FCR** = gold-different merged / gold-different; **MCR** = gold-same not merged / gold-same; retrieval misses and judge parse errors
  stay in the denominators as not merged and are listed; a run that fails its contract is excluded and reported.
- **Intervals:** Wilson 95% for rates; paired percentile bootstrap (B = 10 000, seed 20261014) and exact McNemar for paired contrasts;
  conversation-cluster bootstrap for comparison-level rates and QA; n < 20 flagged indicative; n = 0 reported n/a.
- **Tables by split:** primary = all v2 pairs (dev + test; not blind, disclosed); held-out = test only (indicative, see §1); dev only for
  diagnostics.
- **Seeds:** one seed, greedy decoding; bootstrap over pairs replaces ">= 3 seeds" (Team B acceptance open).
- **QA:** scored with the normaliser each reference names (`qa_norm`): v2 (Indic-safe) for v2 packages, v1 for v1 data; identical
  outside Gujarati script.

## 3. Gate comparisons, lexicon and feature sets

- **Gate effect:** gate lexicon minus gate off on the same pairs (paired, §2); C per mode, D across the frontier (§4).
- **Feature sets:** primary = the frozen cannot-link set (kinship + register); **pre-registered sensitivity = `kinship_only`**
  (`score_v2 --feature-set kinship_only`, Tier 1 `dkmem.eval.sensitivity`), because Member 3 flagged before any v2 result that the
  register expansion multiplies register vetoes and Team B's convention 2 treats a register shift to the same addressee as the same person.
- **Lexicon rule:** Team B's final lexicon is primary iff a per-change log cites a linguistic source or definition and states it is not
  derived from Tier 1/Tier 2 outcomes or test labels; otherwise it is a labelled sensitivity variant. The pre-results lexicon
  (`d555385e`) is always reported (it has no mr/gu entries, so under it gate on = gate off for mr/gu). Offline replay: Tier 1
  `tier1.lexicon_replay`, Tier 2 `score_v2 --lexicon`.
- **C versus D:** C's points against D's frontiers at matched MCR (§4), never against one tau. Tier 1 C (3B) and Tier 2 C (7B) are not pooled.

## 4. Config D threshold frontier

Every distinct logged cosine is a tau (plus one above all); gate off and lexicon; both metric levels; **no tau is selected** (0.90 is an
execution value). Matched-MCR on m = 0.00, 0.05, ..., 1.00: lowest FCR at MCR <= m per mode, lexicon minus off with a relation-stratified
pair bootstrap (B = 10 000, seed 20261014, frontiers recomputed per resample); C minus D at C's MCR. Per feature set (§3).
Implemented in `tier2.score_v2` and `dkmem.eval.cli sweep|compare`.

## 6. Reproducibility, freezing and new inference

| Change | Tier 2 | Tier 1 |
|---|---|---|
| Relabel or drop pairs | rescore (`score_v2`; v1.0 runs via `build_label_dir`) | rescore (key holder) |
| New lexicon or feature set | replay (`score_v2 --lexicon/--feature-set`); QA marked STALE and re-run (QA step only) where final records change | `tier1.lexicon_replay`; `needs_inference` pairs only |
| v2.0 benchmark (changed text, new pairs, new languages) | **new inference: all conversations x 4 runs** | none (no v2 Tier 1 items) |
| Judge in a new language | **new inference: one 7B validation kernel per frozen mr/gu case set** | n/a |

**Judge validation for Marathi and Gujarati (required for C claims):** a native-authored case set per language with the composition of the
Hindi part of `cases_7b.jsonl` (30 cases: 19 controls, 11 probes), disjoint from every v2 sentence, bank and prompt example
(`judge_readiness check-cases`), frozen with its own FREEZE file before the run; `criteria_7b.json` gates applied unchanged, per language.
Team A must not author it (no native speakers).

`eval/tier1/lexicon_replay.py`; `eval/harness/{_dkmem,extractors}.py`; `dkmem/memory/{gate,lexicon,matcher,scope,dkmem_extract}.py`;
`dkmem/pipeline/trace.py`; `dkmem/tier1/{io,extraction}.py`; `dkmem/eval/*.py`; the schemas; the v2.0 package and `FROZEN_v2.0.json`;
Team B's specs, split files and review records; the distractor banks (incl. mr/gu); the final lexicon and its change log; the mr/gu judge
case sets and FREEZE files; v1.0/v1.1m FROZEN files, evaluator inputs and run manifests (bridge and history); Tier 1 group fingerprints;

**Order:** Team B deliverables -> `generate_tier2_v2 validate` passes -> FROZEN_v2.0 -> freeze file -> mr/gu judge validation and v2
runs (Kaggle) -> contract + `replay verify` on the v2 runs -> FINAL scoring.

## 7. Limitations (stated with every result)

Labels' review status; disclosed test exposure (§1); one seed; name_variant and contextual_qualifier confounded with relation; v1.0-retained
kinship pairs also differ in city/weekday (Team B README); Marathi/Gujarati indicative only; judge validated only where §6 passed; Tier 2
built partly from Tier 1 items; final evaluation not blind to v1 provisional results; Tier 2 C backbone differs from Tier 1; tau 0.90 is an
execution value. No claim about "Indic languages" in general.
